## 2. Детали по самому важному изменению (дефект A)

`firmware/src/ota_inapp.c`.

**Было:**

```c
if (s_ota_active && s_ota_progress >= 99 && s_all_crc_ok) {
    ota_install_firmware_and_reboot();
}
```

**Почему это дефект:** `s_ota_progress` — процент от заявленного общего размера, он доходит до 99 %
до прихода последних ~1.5 КБ. `s_all_crc_ok` при этом ещё `true`, потому что проверка CRC последнего
раздела просто **не запускалась** (она выполняется только когда `s_sector_offset >= p->size`).
Итог: обрыв связи на 99 % → установка усечённого образа, при этом boot header описывает полные
размеры разделов. Команда `0x04` (reboot) вообще не проверяла CRC.

**Стало:**

- `static bool s_final_crc_verified = false;`
- сбрасывается в `CMD 0x01` (START_OTA);
- выставляется `true` **только** в ветке `s_current_sector + 1 >= s_sector_count && s_all_crc_ok`;
- `OTA_EVT_DISCONNECTED` устанавливает прошивку только при `s_final_crc_verified && s_all_crc_ok`,
  иначе пишет в лог и остаётся на текущей прошивке;
- `CMD 0x04` при неподтверждённом образе отвечает `send_response(0x8A, 0x04)` и выходит.

**Важно для проверки на железе:** отказ установки — не кирпич. Часы остаются на текущей прошивке,
по разрыву соединения выходят из режима OTA и возвращаются на циферблат. Если после прошивки этой
версии OTA «не встаёт» — это гейт, а не поломка; смотреть лог по UART.

## 10. Правила поведения (кратко)

1. Не прошивать, не запускать OTA-скрипт, не менять OTA-логику до появления провода.
2. `P07` (TM) и `P33` (шлейф дисплея) — **никогда** в OUTPUT/HIGH.
3. I2C — только `P16`/`P17`.
4. Дисплей 80×160: ≤12 символов при scale 1, ≤6 при scale 2.
5. Никаких NOP-задержек — только `WaitMs`/`WaitUs`.
6. `.backups/` не трогать, build-артефакты не коммитить.
7. `.md` — UTF-8; `.bat` — ASCII + `chcp 65001`.
8. После каждой правки: сборка + `python scripts\tools\verify_audit.py`.
