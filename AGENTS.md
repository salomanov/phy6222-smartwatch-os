# Правила проекта (для агента)

Этот файл читается автоматически. Подробности — в `AGENT_HANDOFF.md`.

## СТОП: OTA заморожен

- Не прошивать часы и не запускать `scripts/flash/ota_ble_flash.py`.
- В `firmware/build/` лежит непроверенная сборка — запуск OTA-скрипта зальёт её по воздуху.
- Не менять `firmware/src/ota_inapp.c`, flow-control и выравнивание flash, пока у владельца
  нет доступа к проводу (UART/TM). Восстановление без провода невозможно.

## Железо

- `P07` (TM) и `P33` (шлейф дисплея) — никогда не переводить в OUTPUT/HIGH.
- I2C — только `P16` (SCL) / `P17` (SDA). Повторная инициализация I2C по клику запрещена.
- `P20` — вход АЦП батареи; не удерживать HIGH.
- Никаких NOP-задержек — только `WaitMs`/`WaitUs`.
- Любое действие с пинами на живом устройстве — только с разрешения владельца.

## Дисплей 80×160

- Не более 12 символов в строке при scale 1 и 6 при scale 2.
- Проверять переносы в `gfx_draw_string` при добавлении любого текста.

## Работа с репозиторием

- Не коммитить `firmware/build/*`, `__pycache__`, `.pyc`, `temp_*.bin`.
- `.backups/` не трогать и не удалять.
- `tools/smartwatch_ref` — сабмодуль; внутри него не делать `checkout`/`reset`, его грязное
  состояние (untracked) не коммитить.
- Два `PROJECT_STATE.md` расходятся — не доверять им без сверки с кодом.
- `.md` — UTF-8; `.bat` — ASCII + `chcp 65001`.

## Проверка после каждой правки

```powershell
python firmware\build.py
python scripts\tools\verify_audit.py
```

Ожидается `BUILD SUCCESS` и `[PASS]`, exit code 0. Сборка падает, если OTA-образ не влезает
в staging (160 КБ − 4 КБ) — это защита, а не баг.

## Где что лежит

- `CODE_REVIEW_RECOMMENDATIONS.md` — полное ревью и приоритеты P0/P1/P2.
- `docs/ERRORS_AND_FAILURES.md` — жёсткие правила проекта.
