# PhyPlus PHY6222 SDK & Architecture Digest
> **Краткая инженерная выжимка по архитектуре чипа PHY6222, стеку BLE, памяти и HAL для кастомных прошивок.**

---

## 1. Аппаратная архитектура и карта памяти (Memory Map)

Чип **PhyPlus PHY6222QC**: ядро 32-bit ARM Cortex-M0 (до 64 МГц, штатно 16 МГц), 512 КБ SPI Nor Flash, 138 КБ SRAM, BLE 5.2.

### 1.1. Физические адресные пространства
| Диапазон адресов | Область | Описание |
| :--- | :--- | :--- |
| `0x00000000` - `0x0000FFFF` | **ROM (64 KB)** | Аппаратный загрузчик, базовые BLE-библиотеки, векторные таблицы ROM. |
| `0x11000000` - `0x1107FFFF` | **SPI Flash (512 KB)** | Память программ (XIP — eXecute In Place) и таблицы разделов. |
| `0x1FFF0000` - `0x1FFF3FFF` | **Retention SRAM Bank 0 (16 KB)** | Сохраняет состояние в Deep Sleep. Данные стека BLE и критические буферы. |
| `0x1FFF4000` - `0x1FFF7FFF` | **Retention SRAM Bank 1 (16 KB)** | Сохраняет состояние в Deep Sleep. Векторы прерываний, код из RAM. |
| `0x1FFF8000` - `0x200227FF` | **Extended SRAM (106 KB)** | Общая оперативная память (heap, bss, буферы дисплея, стек вызовов). |

### 1.2. Карта Flash-памяти (512 КБ SPI Flash)
- **`0x11002000` — Bootloader Header (Таблица аппаратного ROM-загрузчика)**:
  - `p32[0] = 4` — количество сегментов прошивки.
  - `p32[2] = 0x1FFF1838` — точка входа (`Reset_Handler` / `phy6222_start`).
- **`0x11002100` — Segment Table (Дескрипторы 4 разделов)**:
  - `Part 0`: Flash `0x11010100` -> Run `0x11010100` (XIP Секция 1, базовые драйверы и ядро).
  - `Part 1`: Flash `0x11020000` -> Run `0x11020000` (XIP Секция 2, приложение часов, шрифты, графика).
  - `Part 2`: Flash `0x11005000` -> Run `0x1FFF0000` (Копируется загрузчиком в Retention SRAM Bank 0).
  - `Part 3`: Flash `0x11005400` -> Run `0x1FFF1838` (Копируется загрузчиком в SRAM Bank 1, точка входа).
- **`0x11003000` — `slboot` 2nd Boot Info Table (Таблица вторичного загрузчика)**:
  - Обязательна при старте часов без зажатого провода `TM`!
  - `0x11003FF0`: Fast Boot Magic `0xA5A55A5A` (обход медленного расчета CRC при старте, быстрый запуск за 50 мс).
- **`0x11040000` — In-App OTA Staging Buffer (256 КБ)**:
  - Буфер для беспроводной записи прошивки без риска затереть рабочий код до завершения проверки CRC.

## 2. Операционная среда OSAL (TI BLE-совместимый планировщик)

Вся логика в PhyPlus SDK построена на кооперативном планировщике **OSAL (Operating System Abstraction Layer)**.

### 2.1. Жизненный цикл
1. **Инициализация**: `osal_init_system()` регистрирует задачи в массиве `tasksArr[]` и выделяет `tasksEvents[]`.
2. **Главный цикл**: `osal_start_system()` крутится в бесконечном цикле, опрашивая маски событий `tasksEvents[idx]`.
3. **Обработчик задачи**:
   ```c
   uint16_t WatchApp_ProcessEvent(uint8_t task_id, uint16_t events) {
       if (events & SYS_EVENT_MSG) {
           // Обработка сообщений из очереди
           return (events ^ SYS_EVENT_MSG);
       }
       if (events & WATCH_TICK_EVT) {
           app_os_update(); // Периодический тик 50 мс
           osal_start_timerEx(task_id, WATCH_TICK_EVT, 50);
           return (events ^ WATCH_TICK_EVT);
       }
       return 0;
   }
   ```

### 2.2. Железные правила OSAL
- **Никаких блокирующих задержек**: функции вида `while(...)`, `delay()`, `WaitMs(>5)` внутри тика замораживают стек BLE, вызывая таймаут соединения (WinError -2147467260 / Connection Lost).
- Все задержки реализуются через таймеры `osal_start_timerEx(task_id, event, timeout_ms)`.

## 3. Аппаратный пинаут платы LP715 (PHY6222QC)

| Пин SoC | Назначение | Полярность / Режим | Правило безопасности |
| :--- | :--- | :--- | :--- |
| **`P07`** | **Hardware TM (Test Mode)** | Вход Bootloader | **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** переводить в OUTPUT HIGH. Приводит к зависанию в ROM. |
| **`P33`** | **Шлейф LCD ST7735** | Сигнальная линия экрана | **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** управлять из кода. Вызывает коллизию шины и черный экран. |
| **`P03`** | **Вибромотор (ERM)** | **Active HIGH** (`1 = ON`, `0 = OFF`) | При OTA всегда держать `0`! При работе от батареи не включать дольше 350 мс. |
| **`P00`** | **Статусный LED** | **Active LOW** (`0 = ON`, `1 = OFF`) | Выключается записью `1`. |
| **`P11`** | **Сенсорная кнопка (Touch)** | Вход, Pull-down | Емкостной сенсор. Чувствителен к просадкам питания от мотора. |
| **`P20`** | **АЦП батареи (ADC)** | Аналоговый вход | Делитель напряжения батареи Li-Po (1S 3.0–4.2V). |
| **`P09`** | **UART TX** | Альтернативная функция | TX часов -> RX адаптера (115200 бод). |
| **`P10`** | **UART RX** | Альтернативная функция | RX часов -> TX адаптера (115200 бод). |
| **`P01`** | **Подсветка экрана (BKL)** | **Active LOW** (`0 = ON`, `1 = OFF`) | Отключается записью `1` для сохранения заряда. |
| **`P24`** | **ST7735 RST** | Сброс дисплея | Управляется драйвером экрана. |
| **`P25`** | **ST7735 DC** | Data / Command | Переключение данных/команд SPI. |
| **`P31`** | **ST7735 CS** | Chip Select | Выбор чипа экрана (Active LOW). |
| **`P32`** | **ST7735 MOSI** | SPI Master Out | Передача пикселей (16 МГц SPI). |
| **`P34`** | **ST7735 SCLK** | SPI Clock | Тактирование матрицы. |

## 4. Стек BLE и беспроводная прошивка (In-App OTA)

### 4.1. Профиль OTA (In-App Service)
- **Service UUID**: `5833ff01-9b8b-5191-6142-22a4536ef123`
- **Control Point UUID (`ff02`)**: Команды старта (`0x01`), передачи заголовка раздела (`0x02`), перезагрузки (`0x04`).
- **Response Point UUID (`ff03`)**: Нотификации статуса (`0x81` старт, `0x84` раздел принят, `0x85` раздел записан, `0x83` OTA завершено).
- **Data Point UUID (`ff04`)**: Поток бинарных данных пакетами до MTU (230 байт).

### 4.2. Формула 100% стабильности OTA
1. **Pacing 12 мс**: Задержка `await asyncio.sleep(0.012)` между чанками дает аппаратному контроллеру SPI Flash время сбросить буфер на кристаллы памяти.
2. **Write with Response**: Запись через `client.write_gatt_char(OTA_DATA_UUID, chunk, response=True)` использует аппаратный ATT ACK от чипа, исключая потерю пакетов в Windows WinRT.
3. **Обесточивание мотора**: Перед началом передачи вызывается `vibrator_stop()` и по UART CLI подается `pin 3 0`. Мотор отключается, исключая просадку 3.3V и радиопомехи.
4. **Прореживание перерисовки**: Прогресс-бар на ST7735 перерисовывается шагами по 5–10%, освобождая 80% времени процессора для обслуживания радиоканала.

## 5. Энергосбережение и спящий режим (Power Management)

- **Контроллер Always-On (`AP_AON`)**: Базовый адрес `0x4000F000`.
- **Гашение экрана**:
  - `display_cmd(0x28);` (DISPOFF — выключение вывода матрицы).
  - `display_cmd(0x10);` (SLPIN — перевод контроллера ST7735 в сон ~10 мкА).
  - `hal_gpio_write(BKL_PIN, 1);` (обесточивание светодиодов подсветки).
- **Пробуждение (Wakeup Sources)**:
  - По внешнему прерыванию GPIO (сенсорная кнопка P11, вход WAKEUP).
  - По событию BLE таймера (BLE Advertising interval, Connection event).
- **Программный сброс (Software Reset)**:
  ```c
  AP_AON->SLEEP_R[0] = 4;
  AP_AON->SLEEP_R[1] = 0;
  AP_PCR->SW_RESET1 = 0; // Аппаратный ресет Cortex-M0
  ```
