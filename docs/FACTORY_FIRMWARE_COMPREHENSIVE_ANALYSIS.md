# Полный технический анализ заводской прошивки браслета LP715_MB_V1.3 (PHY6222QC)
> **Статус документа**: Полный эталонный инженерный отчёт.  
> **Объект исследования**: `factory_dump.bin` (524 288 байт / 512.0 КБ, SHA256: `062c3b3909eb5488f510b9b5185f64784d4a7c6308a07718b7108a40c27c9854`).  
> **Целевой процессор**: SoC PhyPlus PHY6222QC (32-bit ARM Cortex-M0, 138 КБ SRAM, 512 КБ встроенной Flash).

## 1. Карта адресного пространства Flash-памяти (512 КБ)

Базовый адрес Flash в адресном пространстве Cortex-M0: `0x11000000`.

| Смещение во Flash | Виртуальный адрес | Размер | Назначение | Описание и содержимое |
|---|---|---|---|---|
| `0x000000 - 0x001FFF` | `0x11000000 - 0x11001FFF` | 8 КБ | **Аппаратный ROM Bootloader** | Аппаратный загрузчик чипа. Проверяет уровень на пине `P07` (TM). Если `P07 = HIGH` (3.3В), переходит в режим UART прошивальщика на 115200 бод. Если `LOW`, передает управление вторичному загрузчику. |
| `0x002000 - 0x002FFF` | `0x11002000 - 0x11002FFF` | 4 КБ | **Vector Table & Boot Entry** | Таблица векторов прерываний Cortex-M0 (Stack Pointer = `0x1FFF8000`, Reset Vector = `0x11002041`). |
| `0x003000 - 0x003FFF` | `0x11003000 - 0x11003FFF` | 4 КБ | **Secondary Bootloader (`slboot`) Info** | Таблица разделов `OTAF_2nd_BOOTINFO_ADDR`. Содержит 11 записей разделов и маркер Fast Boot `0xA5A55A5A`. Если этот сектор пуст (`0xFF`), загрузчик останавливает старт с кодом `PPlus_ERR_OTA_NO_APP`. |
| `0x004000 - 0x004FFF` | `0x11004000 - 0x11004FFF` | 4 КБ | **Служебные параметры RF & MAC** | Калибровочные данные радиотракта BLE, смещение частоты кварца 16 МГц, публичный BLE MAC-адрес (по умолчанию `62:62:15:07:07:15`). |
| `0x005000 - 0x01FFFF` | `0x11005000 - 0x1101FFFF` | 110 КБ | **BLE Controller & Host Stack** | Стек протоколов Bluetooth LE (GAP, GATT, L2CAP, SMP, LL Link Layer, OSAL планировщик). |
| `0x020000 - 0x03EFFF` | `0x11020000 - 0x1103EFFF` | 124 КБ | **FitPro / Smartwatch OS Application** | Основной код приложения часов: драйверы дисплея ST7735S, SPI, I2C, сенсоров, вибромотора, алгоритмы шагомера и сна, протокол связи `0xCD`. |
| `0x03F000 - 0x04FFFF` | `0x1103F000 - 0x1104FFFF` | 68 КБ | **Шрифты и графические ресурсы** | Таблицы моноширинных и пропорциональных шрифтов ASCII/Unicode `PHY_FONTV1.01.03GB12EU12`, иконки батареи, шагов, пульса. |
| `0x050000 - 0x07FFFF` | `0x11050000 - 0x1107FFFF` | 192 КБ | **OTA Swap Buffer & Data Logs** | Буфер для приёма пакетов прошивки по воздуху, кольцевой буфер шагов и истории пульса за 7 дней. |

> **Все функции драйверов (`hal_gpio_write`, `hal_gpio_pin_init`, `hal_gpio_pull_set`) принимают первым параметром НЕ физический номер ножки, а индекс внутреннего перечисления `gpio_pin_e`!**

## 3. Аппаратная разгадка шины I2C и кварцевого генератора

В ранних сборках сканирование `i2c scan` на пинах `P16/P17` выдавало ложный ACK на всех 112 адресах, либо линия SDA читалась как жесткий 0 (`BUS LOW`).
Деассемблирование кода `0x11020F14` и анализ исходников `gpio.c` выявили аппаратную причину:
1. Ножки `P16` (`XTALI`) и `P17` (`XTALO`) чипа внутри кремния подключены к генератору внешнего часового кварца 32.768 кГц.
2. Встроенная схема смещения генератора принудительно стягивает ножку `P17` к потенциалу земли.
3. Простая настройка `hal_gpio_cfg_analog_io(pin, Bit_DISABLE)` недостаточна, так как аналоговый генератор в блоке AON (Always-On Power Controller, `0x4000F01C`) продолжает функционировать.
4. **Каноническая последовательность освобождения шины**:
   ```c
   // 1. Полное отключение питания аналогового генератора 32кГц (биты 16:7)
   subWriteReg(0x4000f01c, 16, 7, 0x3fb);
   // 2. Включение программного управления ногами через GPIO (бит 6)
   subWriteReg(0x4000f01c, 6, 6, 0x01);
   // 3. Отключение аналогового мультиплексора ADC/IOMUX
   hal_gpio_cfg_analog_io(GPIO_P16, Bit_DISABLE);
   hal_gpio_cfg_analog_io(GPIO_P17, Bit_DISABLE);
   ```

## 4. Заводская таблица самодиагностики и поддерживаемые датчики

По смещению `0x34B00` в дампе обнаружена заводская таблица текстовых строк встроенного теста оборудования:
```
0x11034B00: "G-SC----OK"   -> Акселерометр Silan SC7A20 обнаружен (I2C 0x18 / 0x19)
0x11034B0C: "G-QMA6--OK"   -> Акселерометр QST QMA6100 обнаружен (I2C 0x12)
0x11034B18: "G-QMA7--OK"   -> Акселерометр QST QMA7981 обнаружен (I2C 0x13)
0x11034B24: "G-NONE-ERR"  -> Акселерометр не ответил
0x11034B30: "HR-EM-OK"     -> Оптический сенсор пульса EM7028 обнаружен
0x11034B3C: "HR-SC-OK"     -> Оптический сенсор пульса Silan SC7R30 обнаружен
0x11034B48: "HR----OK"     -> Пульсометр общего типа обнаружен
0x11034B54: "HR---ERR"    -> Ошибка пульсометра
```
Заводская прошивка унифицирована под несколько китайских фабричных партий:
- Если распаян **SC7A20**, он отвечает по адресу `0x18` (или `0x19`), регистр `WHO_AM_I` (`0x0F`) возвращает `0x11`.
- Если распаян **QMA6100**, он отвечает по адресу `0x12`, регистр `0x00` возвращает `0x90`..`0xB9`.
- Оптический пульсометр расположен на отдельном шлейфе на нижней крышке, запитывается через `P00` и использует зеленый LED `P14`.

## 5. Протокол обмена данными FitPro (`0xCD`)

Заводская прошивка работает с мобильным приложением FitPro через кастомный BLE сервис `0xFEE7` / `0xFEE8` с MTU=23 (или 247):
- Все пакеты начинаются с байта-заголовка: `0xCD`.
- Структура фрейма:
  ```
  [0] = 0xCD (Magic Byte)
  [1] = Opcode (Команда)
  [2] = Length (Длина полезной нагрузки)
  [3..N-1] = Payload
  [N] = Checksum (XOR / CRC8)
  ```
- **Основные опкоды**:
  - `0x01`: Синхронизация времени и даты (`CD 01 07 YYYY MM DD HH MM SS`)
  - `0x02`: Передача дневной статистики шагомера (шаги, метры, сожженные калории)
  - `0x03`: Запрос и передача данных пульсометра / сатурации SpO2
  - `0x04`: Установка будильников (до 8 будильников с битовой маской дней недели)
  - `0x08`: Поиск браслета с телефона (чип включает вибрацию `vib 500`)
  - `0x09`: Управление удаленной камерой (касание кнопки шлет сигнал спуска затвора)
  - `0x12`: Push-уведомление (Apple ANCS / Android Notification Service) с передачей текста и имени приложения
  - `0x15`: Двустороннее управление музыкальным плеером (Play, Pause, Next, Prev, Volume)

## 6. Архитектура энергосбережения и сна (Power Management)

Заводская прошивка реализует 3-уровневую модель управления питанием:
1. **Active Run Mode (12-16 мА)**:
   - Дисплей включен, частота ядра 16 МГц или 48 МГц, BLE активен.
   - Таймер бездействия: 5 секунд. Если нет касаний кнопки и взмаха руки, вызывается гашение экрана (`DISPOFF 0x28` -> `SLPIN 0x10` -> `P01 = HIGH`).
2. **Light Sleep / Doze (1.2-2.0 мА)**:
   - Дисплей отключен, таймеры OSAL продолжают отсчет, стек BLE держит интервал рекламы 1000 мс или соединение (Connection Interval 50-100 мс).
3. **Deep Sleep / Retention Sleep (~30-45 мкА)**:
   - Ядро Cortex-M0 остановлено инструкцией `WFI` (Wait For Interrupt).
   - Питание цифрового ядра снижается до 0.9В, банки SRAM 0 и 1 (32 КБ) удерживаются в режиме `Retention` для сохранения переменных ОС.
   - Источники пробуждения:
     - Сенсорный пин `P11` (касание кнопки человеком)
     - Аппаратное прерывание `INT1` акселерометра (взмах руки / двойной стук)
     - Аппаратный таймер пробуждения радиотракта BLE RTC.
