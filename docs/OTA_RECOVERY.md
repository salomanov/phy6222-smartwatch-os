# Риски и процедура восстановления прошивки (OTA & Wire)

В проекте строго разграничены **два сценария восстановления**:

---

## Сценарий 1: Штатный откат на проверенную версию (ПО ВОЗДУХУ / BLE OTA)
> **Когда применяется**: Часы работают, экран светится, BLE активен (`CHASY-STEALTH`), но в новой сборке обнаружен баг или регрессия.

В этом случае **НИКАКИЕ ПРОВОДА НЕ НУЖНЫ**. Восстановление выполняется штатной беспроводной заливкой нашей **проверенной стабильной кастомной прошивки** из несгораемого релизного бэкапа:

```bash
# Прошивка проверенного стабильного релиза по воздуху:
python ota_ble_flash.py
```
или с явным указанием проверенного архива:
```bash
python ota_ble_flash.py --bin .backups/firmware_success_2026-10-14_00-41-21/custom_firmware_ota.bin
```

> [!NOTE]
> **Почему родную заводскую прошивку FitPro нельзя прошить по воздуху?**  
> Заводская прошивка FitPro использует совершенно другой закрытый протокол обновления (GATT-сервис `0xFEE8`, закрытый фрейминг `0xCD`, другие смещения памяти). Наш беспроводной установщик `PPlusOTA` (`ota_ble_flash.py` / `ota_inapp.c`) рассчитан на партиционированные образы нашей кастомной ОС (`custom_firmware_ota.bin`). Поэтому **по воздуху мы восстанавливаемся исключительно нашей проверенной кастомной прошивкой**.

---

## Сценарий 2: Аварийное раскирпичивание (ПО ПРОВОДУ / UART)
> **Когда применяется**: Экстремальная авария («кирпич»), когда часы не включаются, экран чёрный, BLE не появляется (например, питание пропало во время стирания Flash boot-таблиц).

В этом случае Bluetooth физически не работает, поэтому беспроводная прошивка невозможна. Восстановление производится через проводной переходник UART (CH340):

### Что нужно:
- Переходник USB-UART (CH340/FTDI) с уровнями 3.3В.
- Подключение: `TX` (пятак 2) → RX адаптера, `RX` (пятак 5) → TX адаптера, `GND` (пятак 1) → GND.
- Контакт `TM` (пятак 8, P07 чипа): **при подаче питания замкнуть на 3.3В** (переводит SoC в аппаратный ROM-загрузчик чипа `cmd>>:`).

### Варианты прошивки по проводу:
1. **Восстановление нашей проверенной кастомной прошивки**:
   ```bash
   python tools/rdwr_phy62x2.py -p COM5 -b 115200 -e -w firmware/build/custom_firmware.hex
   ```
2. **Либо полный сброс до заводского состояния (FitPro)**:
   ```bash
   python tools/rdwr_phy62x2.py -p COM5 -b 115200 -r .backups/factory_dump.bin
   ```
   *(SHA256 дампа: `062c3b3909eb5488f510b9b5185f64784d4a7c6308a07718b7108a40c27c9854`)*

После завершения проводной прошивки: отключить провод `TM` от 3.3В и кратковременно замкнуть `EN` (Reset) на GND.

---

## 3. Защита от сбоев в коде In-App OTA

Для предотвращения окирпичивания при беспроводной прошивке в `firmware/src/ota_inapp.c` внедрены механизмы:
1. **CRC-верификация разделов**: Перед стиранием и перезаписью boot-таблиц сверяются контрольные суммы `s_running_crc` и `s_parts[i].checksum`. Если хотя бы один байт поврежден при передаче по BLE — установка блокируется, устройство остаётся на текущей рабочей прошивке.
2. **Копирование из SRAM**: Установщик `ota_install_firmware_and_reboot()` выполняется полностью из RAM (`_section_sram_code_`) без вызова функций из стираемого Flash.
3. **Fast Boot Magic**: Запись сигнатуры `0xA5A55A5A` по адресу `0x11003FF0` обеспечивает мгновенный безопасный старт вторичного загрузчика `slboot`.
