# Задание для агента: аудит и доведение проекта «Часы»

**Проект**: `E:\Проекты\Часы` — кастомная прошивка умных часов на SoC PhyPlus PHY6222QC (ARM Cortex-M0), плата `LP715_MB_V1.3`, модель `LP719`.
**Файл создан**: 2026-10-17 по результатам технического аудита (чтение кода, документации, git-истории + контрольная пересборка).
**Как читать**: задачи идут по приоритетам P0 → P2. У каждой есть проблема, доказательство (`file:line`), требуемое действие и критерий приёмки. Не меняй то, что не описано в задаче.

## 0. Жёсткие правила проекта (нарушать нельзя)

Взяты из собственного реестра проекта `ERRORS_AND_FAILURES.md` — это не мои пожелания, а его железные правила:

1. **Пин `P07` — это вход `TM`** (пятак программатора). Подача HIGH переводит SoC в ROM-загрузчик, приложение не стартует. Только вход со слабой подтяжкой к земле. (ошибка 1.2)
2. **Пин `P33` трогать запрещено** — он связан с шлейфом дисплея ST7735, импульсы гасят экран. (ошибка 1.1)
3. **I2C датчика — только `P16` (SCL) / `P17` (SDA)**. Другие пины для I2C трогать нельзя. (ошибка 1.3)
4. **Перепрошивка железа в рамках этих задач запрещена.** Плата не подключена к агенту. Никаких `flash*.py`, `rdwr_phy62x2.py`, `ota_ble_flash.py` — это работа пользователя с устройством.
5. **Файлы `.bat` — только ASCII, окончания строк CRLF.** Кириллица в `.bat` ломает `cmd.exe`. `.ps1` — UTF-8 **с BOM**. (ошибки 4.1, 4.2)
6. **Задержки дисплея — только `WaitMs()`/`WaitUs()` из SDK**, никаких пустых циклов NOP. (ошибка 3.2)
7. Не удаляй `.backups/`, `factory_dump.bin`, `dumps/` — это гарантия восстановления устройства. Файл `factory_dump.bin` имеет SHA256 `062c3b3909eb5488f510b9b5185f64784d4a7c6308a07718b7108a40c27c9854` (сверен, совпадает с задокументированным).

**Критерий приёмки.** `app_os_update()` не содержит вызовов с блокировкой дольше одного тика (50 мс). Поведение UI и виброотклик сохранены.

### P2-4. Устранить дублирование раскладки разделов и добавить сверку CRC в установщик

**Проблема.** Карта разделов живёт в трёх местах и может разъехаться; встроенный установщик не проверяет CRC перед перезаписью boot-таблиц, а при Single Bank нет отката.

**Доказательство.**
- `firmware/src/ota_inapp.c:246-254` — целевые адреса заданы константами (`0x11010100`, `0x11020000`, `0x11005000`, `0x11005400`, строка 247 буквально `// default Part 3`), а не берутся из `s_parts[i].flash_addr`, пришедших от хоста.
- `firmware/src/ota_inapp.c:199-209` — `s_parts[i].checksum` только логируется, сверки с `s_running_crc` нет.
- Дубли: `firmware/build.py`, `ota_ble_flash.py`, `firmware/src/ota_inapp.c`.
- Single Bank: `ota_inapp.c:321-323` (`part_num = 2`, single bank) — отката нет.

**Что сделать.**
1. Формировать boot-таблицы `0x11002000` / `0x11003000` из `s_parts[]`, а не из констант.
